# Price Parameter Tampering

## Context

The objective of this article is to enable readers to exploit price parameter tampering vulnerabilities in web applications by leveraging logic flaws. The focus is on operational techniques that demonstrate how unauthorized changes to pricing can be made, highlighting the critical need for server-side validation. Readers are expected to have a foundational understanding of HTTP headers, web form structures, and the client-server model.

## Theory

### Price Parameter Tampering Basics

Price parameter tampering involves the manipulation of price fields in e-commerce transactions to alter the final charged amount. This vulnerability arises when client-side price parameters are not validated server-side, allowing attackers to change prices and submit unauthorized transaction values.

### Common Price Manipulation Techniques

- **Identify and Modify Price Parameter**: Attackers begin by identifying the price parameter, modifying its value, and then submitting the altered request.
  
- **Hidden Price Field**: Some price fields, although not visible to users, can be modified through client-side inspection, such as using browser developer tools.
  
- **Price Equals 0**: Attackers might change the price parameter to zero, effectively bypassing charges.
  
- **Negative Price**: By submitting a negative price, attackers can potentially induce a credit instead of a charge.
  
- **Price Injection**: This involves injecting special characters or commands to disrupt the price logic, potentially leading to unintended application behavior.

### Impact of Price Tampering

Price parameter tampering reveals significant weaknesses in an application's input validation processes. It can lead to substantial financial losses for businesses due to unauthorized transaction values being processed.

### Mitigation Strategies

To prevent unauthorized price changes, employing server-side validation of price parameters is crucial. Additionally, utilizing cryptographic tokens can ensure that price integrity is maintained throughout transactions.

## Practice

### Manual Exploitation

- **Open Browser Developer Tools**: Launch the developer tools in your web browser to begin inspecting elements.
  
- **Locate Price Parameter**: Within the HTML or JavaScript, identify the price parameter that is susceptible to tampering.
  
- **Modify Price Parameter**: Change the value of the price parameter in the form data to a desired amount.
  
- **Submit Modified Form**: Submit the form with the altered price parameter and observe the server's response to verify if the transaction price has been successfully altered.

**Outcome**: Successful execution results in altering the transaction price, highlighting the vulnerability.

### Automated Exploitation

- **Intercept Request with Burp Suite**: Use Burp Suite to intercept a POST request that contains the price parameter.
  
- **Modify Price Parameter**: Within Burp Suite, change the price parameter to the desired value.
  
- **Forward the Modified Request**: Send the altered request to the server and check if the transaction value has been manipulated.

**Outcome**: Successful manipulation of the transaction value by exploiting the logic flaw.
